# Product opening and catalog loading

Scope: only smoother product opening and loading work. The existing theme, typography, dimensions, content, actions and cart/order logic are retained. No add-to-cart/box animation, intro, Remotion runtime, video or new setting is added.

Product-view dialogs use a280ms CSS transform/opacity entrance, a14px travel and1.5% scale change with a decelerating curve. The existing centering translation, header, independently scrolling body and pinned footer are unchanged. It does not animate layout, blur or photo filters, run a frame-by-frame JavaScript loop, wait for gallery transport, or apply to checkout/reservation. Owner motion OFF and device reduced-motion suppress it. Actual frame rate depends on the device/display;120FPS is not promised.

Only already-authorised public photo URL strings can be reused in server memory. Each request first reads the existing public catalog/hero/gallery RPC and uses only its current paths. Products, enabled state, price, available sizes, coupon rules and permissions are not response-cached. Disabled catalog/hero, removed covers and inaccessible galleries cannot be revived by the URL cache. Namespace is backend plus publishable key, never an owner session; at most2namespaces and2000URL entries per bucket, renewing after55minutes, with concurrent-request coalescing and missing-signature retry. There is no persistent storage or new SQL. Cold server instances still need initial signing.

Cover and gallery reads share public URL identities, so opening a pair avoids creating another token for its already-loaded cover. Gallery images decode asynchronously and the opened main photo has fetch priority. If a gallery response supplies another URL, its replacement is decoded before replacing the working cover; failures and late unmounted responses retain the existing retry/fallback behavior. Only the first two collection photos load eagerly; other cards retain lazy loading. Optional promotion-service code loads when its existing post-paint read begins, preserving content and phase behavior.

Evidence:17unit tests cover fresh prices/availability, public gates, changed paths, backend/bucket isolation, expiry, failures and coalescing. Browser checks at320×568,390×844,768×1024 and1440×1000 retain dialog centering, existing actions, gallery transport independence, motion controls and separate checkout behavior. Local automated click-to-visible observations across the runs ranged94–290ms; these include automation/parallel-test overhead and are not phone field measurements. About/language/dark-mode, promotions and synthetic cart/bargain/order regressions pass without live transactions.

Anonymous real-backend reads from the execution environment on8November2026 returned33products on every read. Two paired observations: ordinary re-signing1026/1031ms versus warmed URL reuse634/1052ms. Signing requests dropped2→0 in both pairs, while public_catalog was freshly read each time. Network variance remains; these few backend observations do not establish a stable page-load percentage or guarantee a particular phone's load time. A production build/type/lint/whitespace check is required before pushing.
