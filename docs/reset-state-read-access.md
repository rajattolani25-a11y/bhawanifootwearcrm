# Reset-state read access

The original 0025 policy granted `anon`/`authenticated` unconditional SELECT on the singleton `store_reset_state` row. An anonymous read-only production check on 2026-11-12 returned HTTP 200 and one row when selecting only `id`; no installation UUID, generation or reset time was printed. The Lovable finding is therefore supported by an actual anonymous read, not only source inspection.

Apply the complete [targeted SQL patch](sql/reset-state-read-access.sql) directly in the existing backend's SQL Editor. Both final checks should be true. Then rerun the Lovable security review. This file bypasses the unrelated migration-history mismatch without replaying or editing old migrations/journal entries. Applying this file never invokes reset, restore or changes business data.

The patch enables RLS, revokes anonymous/PUBLIC SELECT including known column-level grants, replaces the original open policy with an authenticated store-member policy, and adds a restrictive SELECT guard so another permissive legacy policy cannot reopen the row to a non-member. Owner and current staff keep the exact existing SELECT used by `readResetState`/`StoreResetBoundary`. Signed-in pending users, removed staff and callers without a user identity get no rows. Authenticated table writes remain ungranted; existing write policies and other tables are unchanged. Security-definer backup/reset/restore/handover functions keep their original definitions and can access this table as before. No public-catalog dependency reads this table directly.

`tests/reset-state-read-access-db-audit.py` uses an isolated offline PostgreSQL container with the complete schema, installs twice, tests owner/staff/pending/removed/anonymous/empty-identity roles, a second legacy open policy, column-grant revocation, write denial and the existing owner backup path. It hashes every existing public function before/after. This audit does not apply production SQL. Manual application and a successful live recheck/security scan remain required before claiming the production finding is resolved.
