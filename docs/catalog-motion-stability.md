# Hero stability and Spotlight smoothing

Hero previously used its signed image URL as the React key. Renewing that URL could replace the entire banner and replay entrance effects. CatalogHero now retains its instance and keeps the displayed photo until a replacement has loaded/decoded. Late responses cannot replace a newer request. A failed token renewal of the same working image does not erase it; an initially missing photo still uses the existing catalog introduction. Visibility observers stay attached across healthy URL renewals.

The public read adapter adds optional `heroUnavailable: true` only for failed hero reads/validation/signing. CatalogView preserves a previously working hero for that temporary failure. A successful null hero (owner OFF) still removes it, and a disabled catalog remains disabled. The field is a frontend/server-response distinction: no SQL, RPC definition, schema, grant or storage change.

Spotlight now uses CSS transform/opacity transitions on a retained three-photo pool. The incoming preview moves/fades into the centre while the outgoing centre moves/fades out, over650ms. Images are warmed/decoded before a requested advance; a slow request keeps the current pair visible. A temporary outgoing slot preserves the last visible frame across reshuffle boundaries. Pending requests are superseded by newer navigation, filter changes or unmount. Photos remain existing product covers; at most3 image elements are mounted.

Three-second automatic advance, random cycles, arrows/swipe only, exact current-product opening, motion OFF/reduced-motion and hover/focus/touch/offscreen/background behavior remain. No Pause/Play, new dependency, uploaded asset or transaction change is introduced.

Verification uses controlled browser fixtures: three350ms delayed hero token renewals retain the same hero node, failed renewal/optional-read failure preserves it, rapid slow→fast replacement keeps the latest result, and owner OFF removes it. Mid-transition mobile inspection shows both images present/partially opaque with three mounted images; desktop layouts fit320/768/1440 widths. Existing Ivory, themes, About, product actions, recovery and Spotlight suites cover adjacent behavior.45 unit tests, TypeScript, semantic lint and production build pass. No live shop mutation/order/message is executed; real device GPU/network behavior is not claimed from these fixtures.
