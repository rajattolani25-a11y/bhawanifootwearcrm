# Catalog Terms & Conditions

The public catalog footer and Help dialog now have a small Terms & Conditions link. Clicking it opens a scrollable English policy dialog with twelve sections, the current shop name and existing contact information. This is an addition to the existing catalog, not the cancelled redesign. Themes, product cards, Spotlight, posters and payment stages are preserved.

Single-pair and combined-cart checkout show a visually14px native checkbox with the requested wording, “I agree to the Terms & Conditions.” There is no banner, preselected consent or remembered acceptance between new checkouts. New Place order stays disabled until agreement, and both submit handlers check it too. Terms can be opened without checking agreement; closing restores the same checkout and input values. Checkbox selection survives Back/Continue inside the same checkout; starting another checkout resets it. Existing interrupted-order recovery is exempt, preserving the exact saved UUID/payload and recovery after browser restart. No order payload, financial RPC, receipt, stock, coupon rule or database schema changes.

Policy copy lives in catalog-terms.json as a hashed, non-inlined static asset. It is fetched only on explicit opening or link hover/focus intent, never during catalog startup. Calls coalesce and subsequent opens reuse the same successfully loaded policy in memory/browser cache. Failed reads show retry inside the dialog and never replace the catalog or discard the checkout draft. No images, new runtime dependencies, database queries, photo storage or external hosting are added. This is a frontend acknowledgement, not a server-stored legal acceptance ledger.

The owner's requested payment-final policy is expressed as no customer-requested cancellation or change-of-mind refund once paid. The copy explicitly preserves remedies under applicable consumer law for incorrect, defective or unfulfilled orders. The rest retains the approved7-day unworn size exchange, original bill/packaging, manual payment screenshot/verification, cart not reserving stock, displayed charges, bargain expiry and non-stackable discounts. No nonexistent Privacy Policy link is added.

Nested legal dialogs use an optional DialogContent overlayClassName with scoped z60/z61 layers above the existing z51 cart/checkout portals. Other dialogs retain their prior default overlay. Focus starts at the terms heading area without scrolling to the contact link; reduced motion is respected. Long copy scrolls independently above a Back action.
