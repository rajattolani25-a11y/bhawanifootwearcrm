# Bhawani About and performance update

About is accessible from the public catalog's mobile bottom menu and desktop/footer link. It contains only the owner-approved Bhawani Footwear name, Main Road → Near Indore Sweets → Jawahar Nagar → Adhartal → Jabalpur/MP482004 address,10:30AM–10:30PM hours and exact23.2010194,79.9501189 pin. Call/WhatsApp reuse the configured store phone when available. No weekly-off claim, promotional introduction or exchange policy is invented. The approved address, times and pin currently live in CatalogAbout; changing Store settings does not change that fixed location profile.

About is a separate lazy-loaded component. Neither its module nor Google Maps iframe is requested before opening it; closing removes the iframe. The Directions link opens Maps with the exact coordinates. Customer geolocation is not requested by this app. External map availability still depends on Google and the customer's connection; map network access is intercepted in local tests. Initial focus stays on the dialog container, keeping the heading/address visible and avoiding automatic focus inside the map.

Performance changes preserve all products, photos, filters, animations and checkout behavior:

- Existing public catalog metadata remains the required first read. Display settings, offer, hero and product-photo signing then overlap; only hero signing waits for validated hero metadata. Photo paths deduplicate. No SQL definition/RPC/RLS changes, response cache, new permissions or cross-request data cache.
- Product cards have unchanged markup in a memoized component. About/theme/product-dialog changes do not repeat the full collection's React work when its products/callback are unchanged.
- Existing30second metadata refresh indexes previous products by ID once, replacing repeated linear lookups. Changed price/size availability still arrives, unchanged signed covers stay reused, and new photos still trigger their existing signed refresh.
- Across the software, existing photo-signing batches remain100paths each, with at most3 batches per caller concurrently. In-flight deduplication, expiry, bounded memory and logout/reset epoch checks remain intact. Prices/stock are not cached by this image cache.
- The language tree walker now rejects protected product-data/code subtrees as a whole. English/Hindi/Hinglish and newly mounted text still translate; entered/saved protected content remains untouched.

This is traversal work, not a claim that the whole app is40% or99% faster.

## Additional owner/catalog performance work — 2026-11-05

Settings and Catalog Studio previously mounted every hidden panel on entry. They now mount each panel on its first visit and keep visited panels mounted while hidden. Hero/product/promotion editors and maintenance/storage/ownership controls are separate lazy imports. Initial Store/Appearance does not request these six editor modules. Team roles/profiles load on first Team visit, with the same current-owner authorization. Drafts and pending child actions survive tab switching; no keepalive navigation behavior is added.

Public cover signing now uses deduplicated100-path batches with at most3 concurrent requests. A350-product fixture signs four batches (100/100/100/50), returns all350products and verifies the concurrency ceiling. A signing failure leaves fresh product prices and availability intact, and the next metadata refresh retries missing covers. There is no price/stock response cache, new financial TTL, omitted total rows or modified financial RPC. Search uses React's deferred rendering to keep typing responsive; price/stock changes remain urgent. POS thumbnails add asynchronous image decoding.

New local evidence:13catalog-read/promotion unit tests pass; the real owner tab containers with intercepted child services show zero initial heavy-editor requests, first-use loading, hidden panels remaining hidden and drafts retained after revisits. Shared-stock browser checks retain one read/channel, immediate event-driven price/stock refresh, photo URL reuse and a single background-resume refresh. Public collection tests retain sort/style/size grouping, exact product selection and live-price reordering at320/390/768/1440px. These are local synthetic checks, not a measured speed percentage for a real phone or production network.

The existing motion audit now waits for the initial Spotlight entrance to finish before measuring its separate next-product crossfade; both animations are still checked. The previous test sampled both transitions at once after remounting the hero and could report insufficient combined opacity. Spotlight code/choreography is unchanged by this performance update.

The performance work itself needs no SQL. Native promotion uploads separately require the complete manual installer in `docs/sql/catalog-promotions/photo-storage.sql`; local tests do not apply it to the owner's backend. To revert performance changes, revert the dedicated performance commit; don't roll back the independent promotion storage installer or alter shop records.
