# AGENTS

- Stock lives in `product_variants` (article × size); sales go only through the `create_sale` DB function so stock decrement is atomic and race-safe.
- Cost/profit are in separate owner-only tables (`product_costs`, `sale_costs`, `sale_item_costs`) because RLS can't hide columns from staff; `sale_items` SELECT is column-restricted.
- Roles stay in `user_roles`: first signup owner, later signups get no role (pending, no data access) until an owner approves via `set_team_role`; `remove_team_access` revokes. Both keep a last owner, so browser writes stay denied.
- Old JSON data imports via `legacy_id` upserts so re-imports never duplicate.
- Signed-in screens use `_authenticated`; `modules.ts` defines navigation. Inventory groups article sizes. The owner removed Guide/tours; `/guide` is only a legacy redirect to Dashboard. Settings use five owner-only sections, Store first. Catalog Studio is accessed only from the left sidebar/menu, last below Stock Ledger.
- Stock-in and returns go only through `receive_stock` / `process_return` DB functions so stock + ledger stay in sync; bills and labels use the in-page print preview in `src/lib/print.ts` (Thermal/A4/Premium), avoiding mobile popup blocking.
- Supplier repayments go through `record_supplier_payment` to allocate against open purchases; QR and Code 128 encode the same variant scan code so both resolve to one size at checkout.
- Credit repayments go only through `collect_credit_payment`; product photos stay in the private `product-images` bucket and are rendered with short-lived signed URLs.
- Destructive store reset is owner-only through `reset_store_data_v2` (migration 0025); old RPC fails closed. Require a saved, checksummed v2 business + photo backup and exact RESET. Preserve the caller owner; other Auth accounts remain but their app roles are revoked. Orders delete before their parents; file binaries delete only via Storage API with a durable, retryable manifest. Restore v2 only to the same empty backend, atomically, without restoring Auth/team permissions. Owner handover uses `transfer_store_ownership` to an already verified signup; never delete the last owner or reopen first-signup ownership after reset.
- Reset compatibility migration 0028 adds explicit non-null primary-key WHERE predicates to the fixed cleanup allowlist for `safeupdate` databases; never disable the database guard or replay 0025. Applying this definition patch never runs reset. Clear stale maintenance progress on errors; do not claim a failed file cleanup means a committed reset rolled back.
- Coupons require a customer, validate in `coupon_discount` and redeem once per customer inside `create_sale` (row lock + redemption trigger), preventing repeated discounts.
- New articles from POS/Purchase/Products go through `quick_add_product` so variants get a scan code and opening stock is ledgered; cost is saved only for owners.
- Default bill size and thermal width live in `store_settings` (bill_design, thermal_width); POS uses them instead of device storage.
- Password recovery goes through the public `/reset-password` route: the sign-in page calls `resetPasswordForEmail` with `redirectTo` origin + `/reset-password`, and the page saves via `updateUser({ password })` without `current_password` (recovery sessions are exempt).
- Customer/supplier opening balances live in an `opening_balance` column added to dues (owner-only edits for customers); all outgoing messages read the shop name from `store_settings` via `useShop`.
- App language is per-device in `src/lib/i18n.tsx`: a DOM translator swaps exact English phrases from the dictionary (`i18n-dict.ts`) on every screen, so pages need no per-string wiring and unknown text stays English. Outgoing WhatsApp/SMS/share sends are intercepted by `MessageLanguage`, which rebuilds known message lines from free offline templates in `message-templates.ts` (no AI cost).
- Khata builds running-balance statements from existing sales, credit payments, purchases and supplier payments; it never stores a separate ledger, so balances can't drift.
- Any list used for totals reads every row through `fetchAll` (`src/lib/fetch-all.ts`), because the database returns max 1000 rows per request and totals would silently go wrong.
- StorageMeter keeps actual public-table allocation/photo bytes separate from labelled planning ranges. Capacity estimates use explicitly assumed, editable device-only limits (default 500 MB DB/1 GB files), 10% headroom, an item-line-based bill model and observed average photo size with clear starter assumptions. Never present estimates as provider quota readings or guaranteed capacity; never divide all database allocation by bills to claim measured bill size. Missing hero reads suppress photo capacity estimates. Reset may leave allocated pages; preserve shared hero cache current_bytes.
- Public `/catalog` reads only through the `public_catalog` DB function via a publishable-key server fn (no cost/stock counts); anon may read only catalog-visible photos.
- Catalog bookings take stock out immediately (`create_catalog_booking`, BOOKING_HOLD) and return it on cancel/expiry; pickup bills go through `complete_catalog_booking`, which releases the hold and calls `create_sale` in one transaction, so stock never double-counts.
- Product photos are compressed on the device (max 1080px WebP). Gallery files live in the existing private `product-images/<product-id>/` folder; `products.image_url` is the cover, including legacy paths. Products and Catalog Studio load extra angles only when opened. Add supports up to eight photos; cover changes retain other angles. Replace/delete saves the new cover before removing the old file. Public extra angles require optional migration 0027 (`public_catalog_photos` and visible-only signing); missing support keeps the cover working. All bucket files are already included in v2 backup/reset. Product deletion is owner-only, confirmed, and blocked by transaction FKs; archive hides from POS/catalog while preserving history. Never delete photos before the product deletion is confirmed.
- Catalog orders: pickup = advance, local/outside delivery = full payment + server-computed charge via `create_catalog_order`; public tracking only through `track_catalog_order` (order no. + mobile); status history is logged by trigger.
- Catalog festival offer settings live in `store_settings` (offer_*) and are read via `public_catalog_offer`; online-order coupons are checked/redeemed inside `create_catalog_order` (`catalog_coupon_amount`, once per mobile) so the same Rewards coupons work at POS and online.
- Catalog photo inquiry (`PhotoSearch.tsx`) does no automatic matching: it only opens WhatsApp to the store with a prefilled message, because browser-side matching was unreliable. The photo never leaves the device.
- Catalog hero controls live only in owner Catalog Studio. `catalog_hero_settings` is owner-only under RLS; public display reads `public_catalog_hero` and only the saved enabled hero image in private `catalog-hero-images`. Missing hero support/image errors fall back to the existing catalog intro. Offer text never changes checkout discounts. Validate actual image alpha, preserve transparency when compressing, and replace the hero copy only after saving; never delete original product photos or the currently saved hero (including while OFF).
- Catalog-wide gallery, category accents and motion flags live in singleton `catalog_presentation_settings` (migration 0021, explicitly approved). Only these public-safe flags are publicly readable; only owners may update them. Missing storage preserves the working catalog and blocks the owner save with a retry message. Global motion OFF also overrides hero motion; device reduced-motion preferences still apply.
- Owner-selected banner palettes use `catalog_presentation_settings.theme` (approved migration 0023), restricted to the seven IDs in `catalog-themes.ts`. Only the palette ID is public; existing owner update RLS applies. Theme Save stays disabled on an older table. Do not replay old presentation migrations after 0023; they can remove the new column grants.
- Warm Ivory uses Liquid Ivory decorative SVG/CSS background motion only; product, heading, offer, CTA and floor shadow stay fixed. Reuse existing hero `motion` for owner background ON/OFF and presentation `motion_enabled` as master, including the owner preview. OFF keeps static artwork; reduced-motion/off-screen/hidden-tab pauses apply. No new migration/assets. Cream storefront styles are scoped to owner palette `ivory` and customer light mode; never transform the fixed-navigation ancestor.
- Owner catalog editing is at `/catalog-studio`, guarded by `requireOwnerRoute` and owner-gated UI. Only left sidebar/menu navigation links to it, last below Stock Ledger; do not restore top/right or Settings shortcuts. Studio opens to Appearance (saved themes/gallery/category colours/motion); selected theme preview is shared with Design & hero. Full per-product content/gallery/draft publishing is a separate proposal in `docs/catalog-studio-editor-storage.md`; the existing Studio product controls edit only cover photo/catalog visibility, never price/stock/GST.
- WhatsApp & Posters uses browser-only `poster.ts` for six 1080×1920 templates. All themes accept optional promotional text and optional visible fields; blank offers must remain blank and never alter prices/checkout. Reuse existing signed photos and in-stock sizes; Collection Grid crops the same photo, with no 3D asset or added storage. File sharing sends only the artwork; community text is separately editable. Keep the photo guide and opaque-photo fallback.
- Poster campaign presets (`poster-campaigns.ts`) persist only bounded design data in device localStorage, never product/photo/price/customer data. Keep storage failure feedback and runtime validation. Editable headline glyphs must fit the reserved slots; preview/share/export use the same typography options. Built-in campaign offers stay blank.
- Promotion workspace uses container-aware three-column desktop and mounted mobile Product/Design/Preview panels. Theme thumbnails reuse the real poster renderer at 16% resolution, lazy/sequential/debounced and paused offscreen/background; exports stay full resolution. Never enable export of the old dimmed preview while preparing updated artwork.
